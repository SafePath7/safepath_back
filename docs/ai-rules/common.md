# 공통 작업 규칙

## 기존 코드 분석과 재사용

1. 코드 작성·수정 전에 관련 패키지와 기존 구현을 분석한다.
2. Controller, Service, Repository, DTO, Entity, 내부 함수, 의존성 및 호출 관계를 확인한다.
3. 기존 기능을 재사용·확장할 수 있는지 판단한 뒤 새 클래스를 추가한다.
4. 이미 구현된 기능, 인증·알림·WebSocket·공통 함수를 중복 구현하거나 같은 책임의 클래스를 불필요하게 만들지 않는다.
5. 기존 인터페이스와 호출 관계를 유지한다.

## 협업과 코드 보호

- 다른 팀원 담당 코드를 명시적 요청 없이 수정하지 않는다.
- 수정이 필요하면 이유와 영향 범위를 먼저 설명하고 사용자 승인 후 진행한다.
- 기존 API 명세, DB 구조, 공통 설정, 보안 구조, 인터페이스·메서드 시그니처를 임의로 변경하지 않는다.
- 다른 팀원 코드를 불필요하게 리팩터링하거나 자동 포맷으로 대량 변경하지 않는다.
- 요청 범위 밖 문제는 임의 수정하지 않고 보고한다.

## AI 작업 원칙과 범위

- 모든 새 코드에 이 규칙을 적용하고, 기존 코드는 현재 작업에 직접 필요한 부분만 변경한다.
- 컨벤션 적용만을 위해 기존 코드를 대규모 수정하지 않는다.
- 규칙과 기존 코드가 충돌하면 차이점을 보고한다.
- 기존 기능의 동작·호환성을 보존한다.
- 요청 범위에 없는 파일은 수정하지 않으며, 규칙 위반이 필요하면 사전 확인을 받는다.
- 테스트 통과를 위해 운영 코드를 왜곡하거나 테스트 전용 구현에 운영 코드가 의존하게 만들지 않는다.
